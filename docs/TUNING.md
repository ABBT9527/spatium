## 1. 稳定性定理（本项目数值第一戒律）

### 1.1 推导

设某层：成本比 `r`、效果比 `s`、主产能等级 `lv`、周期重置目标取 `lv+lead` 级的成本。

```
重置目标      tgt  = c0 · r^(lv+lead)
本轮收益      ε    = A · V^e_eff          (V = 本轮累计产出，A = 章节常数偏移)
达标所需产出  V*   = (tgt / A)^(1/e_eff)
产能          R    = R₀ · s^lv
本轮耗时      t    = V* / R

⇒ ln t = (1/e_eff)·(ln c0 + (lv+lead)·ln r − ln A) − ln R₀ − lv·ln s

⇒ d(ln t)/d(lv) = ln(r)/e_eff − ln(s)
```

**每轮耗时对产能等级的变化率只由 `e_eff` 决定。** 于是：

| 情形 | 含义 |
|---|---|
| `e_eff < ln r / ln s` | `d ln t/d lv > 0` → 每轮越来越久 → **停留（撞墙）** |
| `e_eff > ln r / ln s` | `d ln t/d lv < 0` → 每轮越来越快 → **发散（塌缩到 0）** |
| `e_eff = ln r / ln s` | `d ln t/d lv = 0` → **每轮耗时恒定** |

定义 **临界弹性 `e* = ln(r)/ln(s)`**。取 **`r = 2.7, s = 2.0` → `e* = 1.4330`**。

## 2. 层参数框架（六层共用同一套引擎）

### 2.1 固定常量

| 常量 | 值 | rationale |
|---|---|---|
| `r`（成本比） | **2.7** | 由"每买 10 次回本时间 ×20"倒推 |
| `s`（效果比） | **2.0** | 翻倍最易心算，降低理解成本 |
| `e*` | **1.4330** | = ln 2.7 / ln 2.0，**不可改**；改 r 或 s 就必须重算 |
| `lead` | 1 | 每轮周期重置推进 1 个产能等级 |
| `kMin` | 1 | 最低产出门槛 V ≥ 10（约 8 s）。v7 的 `kMin=3` 会把最短轮次钉死在 ~9 min，已修正 |
| `R₀` | 1.2 /s | 手动操作的有效速率 |
| 累积项 DF | 增速 0.002 /s，上限 ×1 | 长在线有界奖励；不可购买，不会被复利化 |

### 2.2 三个可调参数 —— 全部由目标反解，禁止拍脑袋

```

                工时 tEnd > tStart ⇒ bonus < 1（目标越来越深）
```

## 2.5 Phase 1 实测修正（2026-10-02，headless 冒烟 `npm run smoke`）

实现跑起来后暴露了 4 处模型与运行时不一致。全部已修，**sim 与 src 现已同源**。

| # | 症状 | 根因 | 修正 |
|---|---|---|---|
| **1** | Θ 从 1 一路爬到 7.6，前 10 轮偏差 20–40% | 模型是**阶跃**的（τ 后立刻 idle），运行时 Φ 是**指数熵衰**（τ_d=60 s）⇒ 等待期实际产能高于模型 | **把衰减显式积分进 solveT**：`V(T)=R·[φ_hand·τ+φ_idle·(T−τ)+(φ_hand−φ_idle)·τ_d·(1−e^(−(T−τ)/τ_d))]`，单调递增 ⇒ 二分求 T |
| **2** | 首轮偏差 43% | c0 的标定基于解析模型，而 Θ₀=1 与真实运行时不匹配 | **Θ₀ 预标定**：用**真实 tick 路径**二分反解（`layers/s1/calibrate.ts`），首轮偏差 → **0.0%** |
| **3** | Φ 在 0.72–0.96 波动，无法稳定到 1.0 | δ\* 用了连续上界的拟合值 `span/(√N−0.5)`，在高估可达距离 | 改用**精确离散最优**：`δ* = ⌊span/(⌈√(N/density)⌉−1)⌋`，density: 方格 1 / 三角格 2/√3 ⇒ 参考最优**恒达 Φ=1.000** |
| **4** | 倍率 2.63× 超出 Q3 上限 | 精确 δ\* 口径下 Φ 上界就是 1.0，而 PHI_HAND 还写着 0.95 | PHI_HAND = **1.00** / PHI_IDLE = **0.40** ⇒ **2.50×**（sim 已同步） |

**关于 Θ 的增长（重要澄清）**：Θ 从 1 涨到 5.4 **不是漂移，是设计需要的斜坡**。
自然增长下每轮耗时是恒定的（`2.7^0.698 / 2 ≈ 1.0`），而目标曲线要求 4 min → 20 min（×5.4），
这个差值只能由 Θ 承担 ⇒ Θ 终值 ≈ tEnd/tStart。**MEMORY 里"Θ 摆动越小越隐形"应理解为"无谓抖动要小"，不是"Θ 不能涨"。**

新增常量：`PHI_DECAY_TAU = 60`、`GOV_DEADBAND = 0.05`（死区：跟踪得住就不动，避免稳态误差被积分器累积）。

**当前验收**（`npm run smoke`）：130/130 轮，偏差均值 4.6% / 最大 6.2%，**PASS**。
（`npm run sim` 主脊 761 h / 95.2 天，命中 95 天目标。）

## 3. Pacing 与体感预算（**已被 §5 v9 口径取代，保留供对照**）

### 3.1 每次 session（4 h）的节奏

| 层 | 单轮均值 | session 内轮数 | session 主要在做什么 |
|---|---|---|---|
| S0 | 4.9 min | ~10 | 点击 / 取极限 / 快速重排 |
| S1–S2 | 10–18 min | 2–4 | 摆点、走线，**重排占约一半时间** |

**这依赖构形引擎成立**：后期不是"等得更久"，而是"一轮要照顾的东西更深"。若砍掉构形玩法，S3 之后的 session 会退化成纯等待 → 表失效 → 整条曲线必须重画。

| 指标 | 目标 | 不合格时的处理 |
|---|---|---|
| 重置耗时带 | 各层见 §2.3（容差 ±15%） | 先调 c0（平移全层），再调 `phaseBonus`（改首末比）；**禁止动 r / s / e\*** |

- 上限 **12 h**（休闲增量常用 8 h；本作后期单轮已达 90 min，需要更宽窗口）
- 离线结算走**同一套纯逻辑**，**禁止第二套公式**（否则两套必然漂移）
- 离线期间不重排：离线收益使用离开时的 Φ

> 起因：用户质询「每层的数值量级在哪、时长怎么测的、有算挂机与操作耗时吗、
> 靠拧数值调时长是否说明架构有问题」。逐条核算后确认 **v8 口径有三处失实**，重写为 v9。
> 脚本：`scripts/sim.mjs`（v8 归档为 `scripts/sim_v8.mjs`）

### 5.1 v8 的三处失实

| # | 失实 | 证据 |
|---|---|---|
| **F1** | **自由度缺失**：2 个自由度 (r,s) 被 1 个稳定约束吃掉，剩余 **0** ⇒ 层间差异只能来自 c0/A 等外部平移常数 | `ln t = (1/e)(ln c0 + (lv+lead)ln r − ln A) − ln R₀ − lv ln s`；稳定条件 `ln r/e = ln s` 与 `e ≔ ln r/ln s` 是同一个式子 |
| **F2** | **时间是一维积分**：`t = V*/R` 里没有任何"做事"的项。380 h 全是等待 | 原模型的 `V(t)` 只有 `dfRate/dfCap` 一个"长在线 ×2"常数，既没区分在线/离线产出，也没计入操作决策耗时 |
| **F3** | **数值量级与时长焊死在同一根轴 (lv) 上**：想要更长必然数字更大，反之亦然 | 见 §5.2 的量级诊断 |

### 5.3 v9 的三个新部件

#### (a) Governor Θ —— 把「等式约束」降级为「负反馈」

```
v8（脆弱）  ：要求 e_eff ≡ e* 精确成立        0.5% 偏差 ⇒ 末轮耗时掉 1/3
v9（稳健）  ：Θ_{n+1} = Θ_n · (T_n / T_target(n))^(−λ)，λ = 0.6
              单步修正限速 ±25%（rateLim = 1.25）
```

`T_target(n)` 是**设计者直接给定的目标曲线**（`tStart → tEnd` 几何插值）。
Θ 乘在目标侧 ⇒ 任何来源的系统性偏差（建模误差、新内容偷偷给的收益）都被自动吸收。

**意义**：不再需要用"精确等式"去换稳定 ⇒ **剩余自由度全部释放给内容系统**。

#### (b) 双档时间模型 —— 第一次区分「在线操作」与「挂机」

```
单轮 = τ 秒的高产档 + 剩余时间的挂机档
  T = τ + max(0, V* − R·φ_hand·τ) / (R·φ_idle)
  φ_hand = 1.00（在线重排 / 做决策；完美玩家 Φ→1.0；Phase 1 实测修正见 §2.5）
  φ_idle = 0.40（挂机、离线；自动求解器维持的中等 Φ 水平）
  τ = min(层操作预算 tOps, 每日注意力上限 7200 s ÷ 每日轮数)
```

日历换算：**ρ = 一天里真正有推进的时间占比**
- 重活跃画像：4 h 在线 + 4 h 离线结算 ⇒ **ρ = 0.333**
- 纯挂机画像：4 h 离线结算 ⇒ **ρ = 0.167**

> **这是 v9 与 v8 最大的结论差异**：v8 暗含 ρ=0.167（"只有在线才产出"）却又给了"长在线 ×2 奖励"，
> 口径自相矛盾，其声称的 380 h ≈ 95 天是**不可核验的**。v9 把两者拆开，日历天数才第一次可算。

#### (c) 尺度轴 Ξ —— 让「数字多大」与「玩多久」正交（v10 升级为显式机制）

Ξ **对称地**乘在产出侧与目标侧 ⇒ **在求 t 的代码里连 Ξ 这个符号都不出现**（可在 `solveT` 中核验）。

> **v9 的 Ξ 是"纯表象"——各层 L0 是手填的，κ 只是把末态顶到目标值。用户因此质疑量级从哪来。**

### 5.6 回答「靠拧数值调时长，是否说明架构有问题」

**是，而 v9 把这条验收写成了脚本里的一张表（表 6）。**

```
时长 = Σ轮数 × 单轮时长
```
两个因子有各自的**硬上限**，都不是可以随便拧的旋钮：

- **单轮时长上限 ≈ 200 min**：再长就不是"一轮要有决策"，而是纯等待
- **轮数上限 = 该层内容条目数**：超出部分全是空转

v9 的 TARGETS 里每层显式标了 `items`（需内容条目数），脚本会输出 `items/runs` 比值：

| 层 | 轮数 | 需条目 | 条目/轮 |
|---|---|---|---|
| S0–S5 | 110–160 | 130–190 | **1.15–1.21** ✓ |

**所以签死一条：调时长的唯一合法方式是 ① 增加内容条目以抬高轮数上限；② 在 200 min 上限内调单轮曲线。**
任何"把 c0 拉大 3 倍但不加内容"的改动，都会让表 6 的比值跌破 1.0 ⇒ 空转 ⇒ 验收不通过。

### 5.7 数值量级阶梯 v10（2026-10-02 · 回答"每层只多几十个数量级"）

> **用户批评**：`1e30 → 1e60` 在对数视角下是 **+30**，是加法。乘法退化为加法 ⇒ 失去膨胀张力。
> 类比：若 S1 到 1e308 收尾，S2 至少要到 1e2000～1e3080；只到 1e616 就等于没涨。

**两条生成规则（结构，不是拍数值）**：

```
跨层   M_k^start = γ_k · M_{k-1}^end
       γ_k = 生产链级数 = 维数 + 1 = 1, 1, 2, 3, 4, 5
       叙述：上一层积累的全部被当作新空间的一把「单位尺」；
              新链有 γ_k 级，每级都吃到这份输入 ⇒ 读数取 γ_k 倍。

层内   Ξ(n) = Ξ₀ · κ^n         κ 由该层终态目标 E 反解
       ⇒ log₁₀(主资源) 本身在层内指数增长，不是线性爬
```

| 层 | γ | 起点 log₁₀ | **末态 log₁₀** | 终态 | 相对上层 | log₁₀log₁₀ |
|---|---|---|---|---|---|---|
| S0 序数 | 1 | 0 | **77** | 1e77 ≈ 2²⁵⁶ | — | 1.89 |
| S1 点 | 1 | 77 | **308** | 1e308 ≈ 2¹⁰²⁴ | ×4.0 | 2.49 |
| S2 线 | 2 | 616 | **2 160** | 1e2160 | ×7.0 | 3.33 |
| S3 面 | 3 | 6 480 | **17 300** | 1e17300 | ×8.0 | 4.24 |
| S4 体 | 4 | 69 200 | **155 700** | 1e155700 | ×9.0 | 5.19 |
| S5 胞 | 5 | 778 500 | **1 556 000** | 10^(10^6.19) | ×10.0 | 6.19 |

**验收标准（写进脚本）**：`log₁₀(末态)` 的逐层比值 ≥ 4，即 **log₁₀log₁₀ 每层至少 +0.6**。
跌破 = 在对数视角下退化成加法 = 不合格（戒律 **N10**）。

**反面教材**：若按"每层 +30 个数量级"做，S5 只有 1e227，与 1e1556000 差 **6850 倍的对数**。

**玩家真正感受到的是"每轮涨多少"**（表 3b 实测）：

| 层 | 首轮 Δlog₁₀ | 末轮 Δlog₁₀ | 层内加速 | 平均每轮数字涨 |
|---|---|---|---|---|
| S0 | +0.43 | +5.69 | ×13.2 | ×10^0.7 |
| S1 | +1.13 | +2.76 | ×2.45 | ×10^1.8 |
| S2 | +5.88 | +18.91 | ×3.22 | ×10^11 |
| S3 | +43.1 | +113.2 | ×2.63 | ×10^73 |
| S4 | +377.9 | +844.8 | ×2.24 | ×10^581 |
| S5 | +3 398 | +6 762 | ×1.99 | **×10^4890** |

**大数库分界线**：S1 末 1e308 = double 上限 ⇒ **S2 开局起 break_eternity 是硬需求**。
终态 10^(10^6.19) 与 Fundamental 终局（≈1e(1e5)）同档偏上；终局无限维段可触及 10^(10^7)（AD Reality 档）。
