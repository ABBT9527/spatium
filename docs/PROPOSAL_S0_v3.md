## 一、对「先单向，再整合」的理解（先确认我没读错）

### 1.1 复述

| 阶段 | 形态 | 玩家体验 |
|---|---|---|
| **阶段 I · 单向** | S0 → S1 → S2 → S3 → S4，**每次只有一个「当前层」** | 线性推图，离开的层留在身后 |
| **阶段 II · 整合** | 完成 S4 后**回到 S0**，但**带着更高阶资源** | S0 被高阶资源加速，飞快重爬 |
| 阶段 II 的突破 | 高阶资源足够多时**冲 S5**；此时**从 S0 开始逐个解锁**，而非直接切到 S1~4 | 不是「跳到 S1」，而是「S0→S1→S2→S3→S4 重新走一遍」，最后 S5 |

**2026-10-02 用户拍板：阶段 II = (b) 同时在线**，理由「**类似基本原理**」。⇒ 不是「顺序重爬」，而是 **S0–S4 同时解锁、同时产出、互相加成**，玩家的动作变成「把阶数往上推」。

### 1.2 这套结构在数学上有干净的读法

- **阶段 I = 沿一条序列走**：把层当成**一个序列**（ω → ε₀ → ζ₀ → Γ₀ → ORD），你一次只站在一个元素上。
- **阶段 II = 把这个序列变成一个对象**：`先单向` 是把层排成**序列**（一维）；`再整合` 是把**整条序列同时握在手里**当作一个可反复施加的算子。

这正是 **Veblen 阶梯的机制本身**：
```
φ₀(α) = ω^α        ← S0 的「换基/幂塔」
φ₁    = φ₀ 的不动点 → ε 数
φ₂    = φ₁ 的不动点 → ζ 数
φ₃    = φ₂ 的不动点 → Γ 数
```
要取**下一个不动点**，你必须**回到最底层、把整个算子重新施加一遍**。所以「完成 S4 后回到 S0」不是设计妥协，而是**取不动点的必要动作**——「先单向，再整合」在数学上就是 **从「枚举一层」升级到「取下一层的不动点」**。

> 一句话：**阶段 I 是 running，阶段 II 是 folding。**
> 用户「类似基本原理」的补充与 (b) 自洽：基本原理的用法正是**把所有下层公理/前件同时摆上台面**，而不是「走完一层丢掉一层」。

### 1.3 但这带来一个**架构变化**（必须现在就知道）

现有引擎是 `meta.current` 单激活层 + `engine.advance()` 只跑当前层。(b) 同时在线要求：

1. **多个层同时存在并同时产出**，不是互斥的「当前位置」；
2. **逐个解锁**意味着「解锁」与「当前」解耦——需要 `unlocked[]` / `active[]` 分离；
3. S0 必须**可重入**（re-entrant）：现在 `s0.ascended = true` 会永久挡住再次涌升，必须改成「可重置并保留元进度」；
4. 阶段 II 的**同时在线**还意味着 tick 要跑多层——性能与「只跑当前层」的旧契约不同（见 §七 实施的 D6 暂缓）。

⇒ **本轮虽只做 S0，但 S0 的设计必须预留「加速输入」钩子**（见 §3.7）。**注：D6 已拍板「暂缓」——现在连 S1 都没开始写，(b) 的引擎改造等 S1 定形后再动。**

## 二、序数渲染：采纳 `testFile/序数渲染测试.html` 的方案

### 2.1 那个 HTML 到底做了什么

1. **输入一个大数 N**，用 `ordFromNat` 把它按**可调底数 b** 展开成序数项（递归：指数/系数也按 b 展开）；
2. **阈值阶梯** `thresholds[0] = b (ω)`、`thresholds[n] = prev ↑↑ b`，即 `thresholds[1] = b↑↑b = ε₀`、`thresholds[n] ≈ ε_{n-1}`；
3. 输出 **LaTeX**（`\omega^{...}`、`\varepsilon_0`、`\varepsilon_0^{...} \cdot ...`）交给 **KaTeX** 渲染；
4. 内建 **lift 折叠**（`needsLift` / `renderLifted`）：当 `ω^e` 超过阈值时提升成 `ε₀^{...}·...`，这正是「ε₀ = ω-幂塔的极限」的呈现；
5. 超出 `maxTerms` / `maxDepth` 时输出 `+\cdots` 截断。

**关键：它与游戏里 `hereditaryToOrdinal(n, base)` 是同一个映射**——只不过它额外做了 ① 渲染到 LaTeX ② 扩展到 ε_n ③ 截断保护。它 page 顶部的提示行 **`底数 b 决定 ω = b 与 ε₀ = b↑↑b。例如 b=2 时 ω=2、ε₀=4；b=3 时 ω=3、ε₀=3^27；b=4 时 ω=4、ε₀=4↑↑4。`** 是 S0「换基即跃升」最直观的展示，也是 §七修正 的**权威出处**。

### 2.2 现状差距

| 项 | 现状（`cnf.ts` 的 `toString`） | testFile 方案 |
|---|---|---|
| 输出 | 裸文本 `ω^1 + 2`（`ω` 显示为 `ω^1`） | LaTeX → KaTeX，真正的嵌套上标 |
| 上标嵌套 | 靠括号消歧（`ω^(ω^1)`） | 排版层天然嵌套，无歧义 |
| 上限 | 封顶 ε₀（见 §七，将改为 `base↑↑base`） | 已支持 ε_n 阶梯 |
| 截断 | 无 | `+\cdots` |

- **R1（本轮做）**：把 `α` 的展示换成 **LaTeX 渲染器 + KaTeX**：
  - 新增 `ordinal/latex.ts`：`Ordinal → LaTeX`（覆盖 `< ε₀` 的全部形态：有限、`ω^β·c`、`ε₀`）；
  - UI 用 `KatexText.vue`（`katex.renderToString` + `v-html`；参考同辈项目 `ordinal-game/src/components/KatexText.vue`）；

## 三、S0 v3 内容方案

### 3.1 三个动词（+ 三条映射）

| 动词 | 数学 | 效果 | 代价 |
|---|---|---|---|
| **后继 Succ** | `α+1` | `n += succGain`（默认 1） | 免费（点击 / 自动） |
| **极限 Limit** | `sup`（跳到下一主序数） | `n ← base^(m+1)`，**跃迁一级台阶** | **极限槽满**（后继充能） |
| **换基 Rebase** | 换基 | `base−1`，`n → 0` | **门槛**（逐次抬高，见 §3.3） |

映射恒为 `α = V_base(n)`（现有 `hereditaryToOrdinal`，**唯一需改的是封顶阈值 → §六**）。

### 3.2 极限操作（本轮最核心的新内容）

**台阶定义**：第 `m` 级台阶 ⟺ `n = base^m`（m = 1,2,3,…）。
- 这是「**base 进制下表示长度 ≥ m+1 位**」的数值刻画；
- 显示序数 `α = V_base(base^m) = ω^{V_base(m)}` 由内核直接算出；
- **base = 2 时台阶为 n = 2, 4 → α = `ω` → `ω^ω`**；而按 §六 的修正（**ε₀ = base↑↑base**），base = 2 时 **ε₀ ⟺ n = 4**——即 `ω^ω` 在 base 2 下被 lift 成 `ε₀`。
- ⇒ **base 2 段的终局 = 从 0 数到 4，共 4 次后继，0 次极限跃迁**（用户 2026-10-02 补充：「当基为 2 时 ε₀ 在值上与自然数 4 相等，此处要进行 **4 次后继**，而非四次极限跃迁」）。**纠正了 v3.0 里「base 2 = 4 次极限」的错误口径。**

**极限槽（充能制）【D1 = (a) 已拍板】**：
- 后继每次 `+chargePerSucc`（默认 1）；
- 槽容量 `LIMIT_CHARGE`（默认 100）；
- 槽满时「极限」可用；极限消耗整槽。

⇒ **后继永远是必需的**（它是极限的燃料），避免「有了极限，后继就废了」这个常见塌陷。

### 3.3 换基门槛：**逐次抬高**（**D2 = 台阶门槛 已拍板**）

| | 序数门槛（未采纳） | **台阶门槛【采用】** |
|---|---|---|
| 定义 | `α ≥ ω^(2+k)` | `台阶 ≥ 2+k`，等价 `n ≥ base^(2+k)` |
| 所需**极限次数** | 2,3,4,5,6,**5,4,3** ← **先升后降** ✗ | **2,3,4,5,6,7,8,9** ← 严格递增 ✓ |
| 原因 | 小 base 下 `ω^ω` 极便宜（base 3 时 n=27 即 `ω^ω`，瞬间越过 ω⁹） | 用「位数」计量，不受幂塔塌陷影响 |

**合计**：`Σ_{k=0..7}(2+k) = 44` 次极限 → base 2；base 2 段按 §六 修正**只需 4 次后继（0 次极限）** ⇒ **S0 全程 = 44 次极限跃迁 + 4 次后继**。

**整条门槛表（base 10 → 2）**

| 换基 k | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 终 |
|---|---|---|---|---|---|---|---|---|---|
| base | 10 | 9 | 8 | 7 | 6 | 5 | 4 | 3 | 2 |
| 门槛（台阶） | ω² | ω³ | ω⁴ | ω⁵ | ω⁶ | ω⁷ | ω⁸ | ω⁹ | ε₀ |
| 需 `n ≥` | 100 | 729 | 4096 | 16807 | 46656 | 78125 | 65536 | 19683 | **4** |
| **极限次数** | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | **0**（4 后继） |

> 注：即使采用台阶门槛，**所需 n 的绝对值仍会先升后降**（因为 `base^m` 随 base 下降而变小）——这正是「换基让一切变便宜」的体现，**是设计意图而非 bug**。所需的**极限次数**（真正的玩家工作量）严格递增。

### 3.5 升级表（花**本层 0阶货币 = 计数 n**）✅ 已落地

## 六、修正 A · **ε₀ 阈值 = `base↑↑base`**（本轮最重要的数学修正）

### 6.1 问题

内核把封顶写成**常量**：`EPS_DEPTH = 3`，`heredWalk` 在 **ω-深度 ≥ 3** 时返回 ε₀（`cnf.ts:163/195`）。于是 base = 2 时 ε₀ ⟺ **n = 16**（`2^(2^2)`）。
但渲染器（`testFile/序数渲染测试.html:36`）的约定是 **`ε₀ = b↑↑b`**：

> 底数 b 决定 ω = b 与 ε₀ = b↑↑b。例如 **b=2 时 ω=2、ε₀=4**；b=3 时 ω=3、ε₀=3^27；b=4 时 ω=4、ε₀=4↑↑4。

两者在 **base = 3 恰好重合**（`3↑↑3 = 3^27` = 深度 3），所以一直没暴露；**base = 2 时差 4 vs 16**。

### 6.2 修正

**封顶阈值从「常量深度 3」改为「深度 ≥ 当前 base」**：

```
ε₀ ⟺ 领先幂塔高度 ≥ base  ⟺  n ≥ base↑↑base
```

| base | ε₀ 的 n 阈值 | 校验 |
|---|---|---|
| 2 | **4** = 2↑↑2 | ✓ 用户补充；✓ 渲染器「b=2 时 ε₀=4」 |
| 3 | **27** = 3↑↑3 = 3^27 | ✓ 同辈项目 `寻数之序`：「ε₀ 自然数下标 = 3^27」 |
| 4 | 4↑↑4（天文数，Decimal 域） | ✓ 渲染器「b=4 时 ε₀=4↑↑4」 |

**base 2 的台阶表随之变为**：

| n | 1 | 2 | **3** | **4** |
|---|---|---|---|---|
| α | `1` | `ω` | `ω+1` | **`ε₀`**（`ω^ω` 被 lift） |

⇒ **base 2 段 = 4 次后继**（0→1→2→3→4），0 次极限跃迁。**「4 阶」的旧口径（n=1/2/4/16）作废。**

### 7.1 后继 / 极限 的原始定义（`G:\workplace\ordinal\对话.txt:110`）

> 「另取一个卡片『序数』，将点击加速按钮换为『后继』与『极限』放入其中，**每后继一次可以将 count+1**，**当每一项中有数值超过基数 3 时，可以进行极限**，每次极限使最大的项包含超过基数的常数转换为序数 ω」

| 动词 | 定义 | 示例（base 3） |
|---|---|---|
| **后继 Succ** | 常数项（finite count）+1 | `3` → 后继×3 → `ω+3` |
| **极限 Limit** | **按基数进位**：最大的、系数 ≥ base 的项进一级幂 | `ω·2` → `ω·3` → `ω²`；`ω³` → `ω^ω` |

**关键差异（本作要吸收的）**：它的「极限」是**进位**（carry），门槛是「**某项系数 ≥ base**」；本作 v3 的「极限」是**跳台阶**（sup，`n ← base^(m+1)`），门槛是「**极限槽满**」。两者可以共存：**进位 = 每一级台阶内部的细粒度推进，跳台阶 = 一次性跨级**。

| 0 | 10 | ω² | 100 | `ω^2`（精确等于） | 2 |
